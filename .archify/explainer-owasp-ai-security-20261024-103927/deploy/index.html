OWASP cho AI Security: ba bộ Top 10 cần nắm

Long image

A

Answer

OWASP có ba bộ Top 10 cho AI: LLM Applications 2025, Agentic Applications 2026 và MCP Top 10. Chúng lần lượt bảo vệ ứng dụng LLM, agent tự hành động và tầng kết nối tool. Rủi ro số một ở cả ba là lệnh độc trong dữ liệu đầu vào. Vì vậy phải giới hạn thiệt hại bằng kiến trúc, không chỉ dựa vào bộ lọc.

  1. LLM Top 10 2025 bao phủ ứng dụng hỏi đáp, RAG và output của model; LLM01 Prompt Injection đứng đầu.1
  2. Agentic Top 10 2026 (ra ngày 9/12/2025) nhắm vào agent có quyền gửi mail, chạy lệnh, gọi API; ASI01 Agent Goal Hijack đứng đầu.2
  3. MCP Top 10 tập trung vào MCP server, token và tool poisoning; bản hiện tại là v0.1, đang thử nghiệm.3
  4. Agent cũng là ứng dụng LLM, nên một hệ thống agent phải xét cả ba bộ cùng lúc.

Mỗi bộ OWASP bảo vệ tầng nào của hệ thống AI?

Diagram structure
  • Người dùng user
  • Nội dung ngoài content
  • Ứng dụng LLM app
  • Model model
  • Kho RAG rag
  • Agent agent
  • MCP server mcp
  • Tool và API tools
  • Chuỗi cung ứng supply
  • user → app · prompt
  • content → rag · tài liệu
  • app → model · gọi model
  • rag → app · ngữ cảnh
  • app → agent · giao việc
  • agent → mcp · gọi tool
  • mcp → tools · thực thi
  • supply → model · trọng số
  1. Người dùng ↗

    Prompt injection trực tiếp và jailbreak đi vào từ đây (LLM01).

  2. Nội dung ngoài ↗

    Email, web, PDF, ảnh chứa lệnh ẩn: prompt injection gián tiếp (LLM01, ASI01).

  3. Ứng dụng LLM ↗

    Lộ system prompt, lộ dữ liệu, output không được kiểm soát (LLM02, LLM05, LLM07).

  4. Kho RAG ↗

    Đầu độc kho tài liệu, rò dữ liệu vượt quyền (LLM08, ASI06).

  5. Agent ↗

    Quyền quá mức, bị chiếm mục tiêu, lỗi lan dây chuyền (LLM06, ASI01–ASI10).

  6. MCP server ↗

    Tool poisoning, token lộ, server giả mạo (MCP01–MCP10).

  7. Chuỗi cung ứng ↗

    Model độc, package giả, data poisoning (LLM03, LLM04, ASI04, MCP04).

OWASP Top 10 for LLM Applications 2025 gồm những gì?

MãRủi roÝ nghĩa ngắnPhòng chống chính
LLM01Prompt InjectionLệnh độc trong input hoặc tài liệu làm model đổi hành vi.Tách dữ liệu không tin cậy, giới hạn quyền, người duyệt hành động nguy hiểm.
LLM02Sensitive Information DisclosureModel hoặc RAG trả về dữ liệu mật, PII, secret.Lọc dữ liệu trước khi đưa vào, phân quyền theo người dùng.
LLM03Supply ChainModel, dataset, thư viện hoặc plugin bị chèn mã độc.Quét file model, dùng safetensors, lập AI-BOM, ký số.
LLM04Data and Model PoisoningDữ liệu huấn luyện hoặc fine-tune bị cài backdoor.Kiểm soát nguồn dữ liệu, đánh giá model sau huấn luyện.
LLM05Improper Output HandlingOutput đưa thẳng vào trình duyệt, shell, SQL gây XSS hoặc injection.Coi output là input không tin cậy; encode và kiểm tra.
LLM06Excessive AgencyỨng dụng cho model quá nhiều tool, quyền hoặc tự chủ.Quyền tối thiểu, tool hẹp, human-in-the-loop.
LLM07System Prompt LeakageSystem prompt lộ ra, kèm secret hoặc luật nội bộ.Không đặt secret trong prompt; kiểm soát quyền ở backend.
LLM08Vector and Embedding WeaknessesKho vector bị đầu độc hoặc trả tài liệu vượt quyền.Phân quyền trong RAG, kiểm tra nguồn tài liệu.
LLM09MisinformationModel bịa thông tin, kể cả tên package không tồn tại.Đối chiếu nguồn, kiểm tra package trước khi cài.
LLM10Unbounded ConsumptionLạm dụng API gây tốn chi phí, từ chối dịch vụ, đánh cắp model.Rate limit, hạn mức chi phí, giám sát sử dụng.

OWASP Top 10 for Agentic Applications 2026 gồm những gì?

MãRủi roÝ nghĩa ngắnPhòng chống chính
ASI01Agent Goal HijackVăn bản agent đọc được lái mục tiêu của agent sang ý kẻ tấn công.Tách nội dung không tin cậy, xác nhận lại mục tiêu trước hành động lớn.
ASI02Tool Misuse and ExploitationAgent dùng tool hợp lệ theo cách gây hại.Least agency: tool hẹp, tham số được kiểm tra.
ASI03Identity and Privilege AbuseAgent mượn hoặc leo thang danh tính, quyền của người dùng.Danh tính riêng cho agent, token ngắn hạn, quyền theo tác vụ.
ASI04Agentic Supply Chain VulnerabilitiesTool, plugin, agent bên thứ ba hoặc MCP server bị chèn mã độc.Danh mục thành phần được phép, kiểm tra và ghim phiên bản.
ASI05Unexpected Code Execution (RCE)Agent sinh hoặc chạy code ngoài dự kiến.Sandbox, không chạy code trên máy có secret.
ASI06Memory and Context PoisoningBộ nhớ dài hạn hoặc ngữ cảnh bị cài thông tin độc.Kiểm tra dữ liệu ghi vào bộ nhớ, tách bộ nhớ theo người dùng.
ASI07Insecure Inter-Agent CommunicationTin nhắn giữa các agent bị giả mạo hoặc chặn.Xác thực và ký tin nhắn giữa agent.
ASI08Cascading FailuresLỗi một agent lan qua cả chuỗi agent.Giới hạn phạm vi, circuit breaker, kiểm tra ở từng bước.
ASI09Human-Agent Trust ExploitationAgent thuyết phục người dùng duyệt hành động nguy hiểm.Hiển thị rõ hành động và rủi ro trước khi duyệt.
ASI10Rogue AgentsAgent hoạt động ngoài phạm vi, không còn kiểm soát được.Giám sát hành vi, kill switch.

OWASP MCP Top 10 gồm những gì?

MãRủi roÝ nghĩa ngắn
MCP01Token Mismanagement and Secret ExposureToken dài hạn, secret hard-code bị lộ qua prompt injection hoặc log debug.
MCP02Privilege Escalation via Scope CreepQuyền của MCP server phình dần vượt nhu cầu.
MCP03Tool PoisoningMô tả tool chứa lệnh ẩn; tool đổi hành vi sau khi được tin (rug pull).
MCP04Software Supply Chain Attacks and Dependency TamperingPackage hoặc MCP server giả mạo, dependency bị sửa.
MCP05Command Injection and ExecutionTham số từ model chạy thành lệnh trên server.
MCP06Intent Flow SubversionNội dung trong ngữ cảnh lái luồng ý định của agent.
MCP07Insufficient Authentication and AuthorizationMCP server không xác thực hoặc phân quyền đủ chặt.
MCP08Lack of Audit and TelemetryKhông có log để biết tool nào đã chạy, với tham số gì.
MCP09Shadow MCP ServersMCP server tự dựng, nằm ngoài quản trị bảo mật.
MCP10Context Injection and Over-SharingNgữ cảnh dùng chung làm dữ liệu của tác vụ này lọt sang tác vụ khác.

Trạng thái MCP Top 10

OWASP ghi MCP Top 10 là dự án incubator, phiên bản 0.1, đang ở giai đoạn thử nghiệm. Tên mục ổn định để trích dẫn, nhưng thứ hạng có thể còn đổi.

Lethal trifecta

Không để một agent cùng lúc có ba thứ: dữ liệu riêng tư, nội dung không tin cậy và kênh gửi dữ liệu ra ngoài. Chưa có cách chặn prompt injection 100%, nên cắt bớt một trong ba thứ trên là cách giới hạn thiệt hại chắc chắn nhất.
