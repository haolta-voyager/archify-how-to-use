01

Vấn đề là gì?

Agent có mọi quyền mà bạn có

  • Đọc toàn bộ repo và thường cả thư mục home: .env, ~/.aws/credentials, ~/.ssh, ~/.npmrc.
  • Chạy shell với quyền của bạn, có mạng ra ngoài, push được lên remote.
  • Dùng mọi CLI đang đăng nhập sẵn: gh, aws, gcloud, kubectl, npm, docker.

Dữ liệu chính là lệnh

  • Mọi thứ agent đọc được (README, comment trong code, file dependency, trang docs, kết quả MCP, log lỗi) đều có thể chứa chỉ dẫn.
  • Chỉ dẫn có thể ẩn với người: chữ trắng, comment HTML, ký tự Unicode vô hình. Model vẫn đọc được.
  • Model không phân biệt được đâu là lệnh của bạn. Model tốt hơn chỉ làm tỷ lệ bị lừa thấp đi, không về 0.

Lethal trifecta trên máy dev

  • Dữ liệu nhạy cảm (secret, repo private) + nội dung lạ (dependency, docs, MCP) + đường ra ngoài (curl, git push, npm publish).
  • Coding agent cấu hình mặc định có đủ cả ba ngay từ đầu.

Nút "Cho phép" không phải là ranh giới

  • Auto-approve, YOLO mode, --dangerously-skip-permissions biến mọi injection thành lệnh chạy ngay.
  • Ngược lại, hỏi xác nhận mọi thứ khiến dev bấm Enter theo phản xạ (OWASP ASI09). Lệnh dài nối bằng && không ai đọc hết.
  • Lời giải ở phần Phòng thủ: allowlist lệnh an toàn + sandbox, để chỉ phải hỏi ở vài lệnh thật sự rủi ro.

Coding agent là một user có quyền rất cao trên máy bạn, nhưng nghe lời bất kỳ ai viết được chữ vào thứ nó đọc.

02

Bị tấn công thế nào? Sáu cửa vào

Cửa 1 và 2 là prompt injection; cửa 3, 4, 5 là chuỗi cung ứng; cửa 6 là cả hai, không có người giám sát.

1 · Nội dung agent đọc: injection khiến agent tự tắt phòng thủ

  • CVE-2025-53773 (GitHub Copilot trong VS Code, vá 8/2025): lệnh ẩn khiến agent ghi "chat.tools.autoApprove": true vào .vscode/settings.json, tự bật chế độ chạy không hỏi rồi thực thi lệnh.
  • CurXecute CVE-2025-54135 (Cursor, vá ở 1.3): injection ghi .cursor/mcp.json, MCP server mới khởi động ngay không hỏi. MCPoison CVE-2025-54136: sửa MCP đã được duyệt mà không bị hỏi lại.
  • Bài học: thư mục cấu hình của agent phải nằm ngoài vùng agent được tự ghi.

2 · File rule, skill và plugin

  • CLAUDE.md, AGENTS.md, .cursorrules, .github/copilot-instructions.md được agent đọc như chỉ dẫn hệ thống. Một PR sửa file này đổi hành vi agent của cả team.
  • Rules File Backdoor (Pillar Security, 3/2025): chỉ dẫn ẩn bằng ký tự Unicode vô hình khiến Cursor và Copilot chèn script độc vào code sinh ra; reviewer không thấy trong diff.
  • ClawHavoc (2/2026): hàng trăm skill độc trên ClawHub giả công cụ phổ biến, kèm bước "cài đặt trước" chạy mã đánh cắp dữ liệu. OWASP tách riêng lớp này thành Agentic Skills Top 10 (AST01–AST10).

3 · MCP server

  • Cài MCP server là cài dependency có quyền chạy: npx, uvx tải bản mới nhất mỗi lần, token plain text trong file JSON.
  • Tool poisoning: một dòng ẩn trong mô tả tool đủ điều khiển agent; tool còn đổi được mô tả sau khi đã được tin dùng.
  • postmark-mcp (9/2025, Koi Security): 15 bản đầu sạch, bản 1.0.16 thêm một dòng BCC mọi email agent gửi về kẻ tấn công.
  • GitHub MCP (2025) lộ repo private qua PR public; Supabase MCP chạy service_role đọc bảng token qua ticket hỗ trợ. Riêng tháng 1–2/2026 đã có hơn 30 CVE nhắm vào MCP.

4 · Extension của IDE: Claude Code trên Cursor Marketplace (29/10/2026)

  • Bản anthropic.claude-code@2.1.313 bị cài cắm xuất hiện trên Cursor Marketplace khoảng 11 giờ (09:27–20:35 UTC), tối đa khoảng 5.000 người dùng. Anthropic không build bản này; bản trên Open VSX, VS Code Marketplace và npm đều sạch.
  • 66 dòng ở đầu extension.js chạy ngay khi editor nạp extension: thêm khóa SSH svc-telemetry vào authorized_keys, mở reverse tunnel ssh -R, cài persistence giả tên hệ thống (LaunchAgent com.apple.sysmond, scheduled task SysMon, cron @reboot), gửi tên biến môi trường chứa KEY, TOKEN hay SECRET.
  • Không cần prompt injection: kẻ tấn công nhắm vào công cụ AI vì nó được cài khắp nơi, tự cập nhật và được tin theo thương hiệu.

5 · Package AI gợi ý (slopsquatting)

  • Nghiên cứu 2025 (USENIX Security, 576.000 mẫu code): khoảng 20% tên package được gợi ý không tồn tại, và nhiều tên lặp lại ổn định nên đoán trước được.
  • Kẻ tấn công đăng ký sẵn những tên đó với mã độc trong postinstall; agent tự chạy npm install hay pip install, không ai nhìn tên package.

6 · Agent trong CI

  • Clinejection (2/2026): tiêu đề một issue khiến bot triage dùng AI của Cline chạy npm install từ commit của kẻ tấn công, đầu độc cache CI, lấy token npm và phát hành cline@2.3.0 trái phép.
  • Comment and Control (4/2026): tiêu đề PR và comment HTML ẩn đủ để lấy API key và GITHUB_TOKEN từ Claude Code Security Review, Gemini CLI Action và Copilot Agent.
  • Ai mở được issue hay PR là người viết prompt cho agent của bạn.

Kẻ tấn công không cần chạm vào máy bạn. Chỉ cần viết chữ vào chỗ agent sẽ đọc, hoặc chen vào chuỗi cung ứng của chính công cụ AI.

03

Hậu quả ra sao?

Thứ bị mất

  • Secret và token: s1ngularity (8/2025), mã độc trong gói Nx gọi Claude, Gemini, Q CLI với cờ bỏ qua xác nhận để tìm secret, rồi đẩy lên repo public trên chính tài khoản GitHub của nạn nhân; hơn 2.000 secret bị lộ.
  • Cả máy dev: khóa SSH lạ, reverse tunnel và persistence như vụ extension 10/2026.
  • Code private: GitHub MCP (2025) tự đăng dữ liệu repo private lên PR public.
  • Dữ liệu và hạ tầng: Amazon Q Developer 1.84.0 (7/2025) bị một PR độc chèn prompt yêu cầu xóa file hệ thống và tài nguyên AWS. AWS cho biết prompt sai định dạng nên không chạy được.

Lan ra ngoài máy một người

  • Chuỗi lây: máy một dev → token npm, GitHub, cloud → package, CI, production → người dùng của bạn.
  • Clinejection: một issue → token npm → cline@2.3.0 tới máy người dùng Cline.
  • Shai-Hulud (9/2025): sâu npm lấy token từ máy nạn nhân rồi tự phát hành bản độc cho mọi package người đó sở hữu, cho thấy bước cuối tự động hóa được.

Không cần kẻ tấn công

  • Replit (7/2025): agent xóa database production giữa lúc đóng băng code dù được dặn không đổi gì, rồi báo sai là không khôi phục được.
  • Gemini CLI (7/2025): lệnh tạo thư mục thất bại nhưng agent không nhận ra, các lệnh di chuyển sau đó ghi đè và làm mất file của người dùng.
  • Giới hạn quyền chặn được cả kẻ tấn công lẫn lỗi của chính agent.

Lỗ hổng đi vào production qua code AI viết

  • Ghép chuỗi vào SQL, shell; eval hay pickle.loads trên dữ liệu ngoài; quên kiểm tra quyền sở hữu tài nguyên.
  • Mặc định không an toàn: verify=False, CORS mở, JWT không kiểm tra thuật toán, secret hard-code "để chạy thử".
  • Khi bị yêu cầu làm test pass, agent có thể sửa hoặc xóa test.
  • GitGuardian (2025): repo có dùng Copilot có tỷ lệ lộ secret cao hơn khoảng 40% so với mặt bằng chung.

Một agent bị lừa trên máy một dev có thể trở thành mã độc trên máy người dùng của cả công ty.

04

Phòng thủ thế nào?

có demo

Mỗi lớp cắt bớt một vòng của lethal trifecta. Lớp mềm chặn phần lớn sai sót vô tình; ranh giới thật chặn khi lớp mềm đã thua.

1 · Quyền: cấu hình như IAM cho một service

  • Deny đọc .env, *.pem, ~/.ssh, ~/.aws.
  • Deny agent tự sửa cấu hình của nó: .claude/, .vscode/settings.json, .cursor/mcp.json (trả lời trực tiếp CVE ở cửa 1).
  • Allowlist test, lint, build; hỏi ở lệnh có mạng, git push, npm install.
  • Hook chặn lệnh nguy hiểm: PreToolUse trong Claude Code chạy script của bạn trước mỗi lệnh. Commit cấu hình vào repo để cả team dùng chung.
// Claude Code: .claude/settings.json
{
  "permissions": {
    "deny": [
      "Read(./.env*)",
      "Read(./**/*.pem)",
      "Read(~/.aws/**)",
      "Read(~/.ssh/**)",
      "Edit(./.claude/**)"
    ],
    "allow": ["Bash(npm test:*)", "Bash(npm run lint:*)"],
    "ask": ["Bash(git push:*)", "Bash(npm install:*)", "WebFetch"]
  }
}

Rule deny trong file cấu hình chỉ là lớp mềm. Ranh giới thật phải nằm ở OS hoặc container.

2 · Sandbox: ranh giới ở OS, không ở prompt

  • Sandbox có sẵn của công cụ: Claude Code /sandbox giới hạn file và mạng ở mức OS; Codex CLI --sandbox workspace-write mặc định tắt mạng.
  • Devcontainer hoặc VM: không mount ~/.ssh, ~/.aws, Docker socket.
  • Chặn mạng ra ngoài, chỉ cho phép registry và domain cần thiết.
  • Muốn chạy YOLO thì chỉ trong container không credential, không mạng. Sandbox còn giảm số lần hỏi, nên dev đọc kỹ hơn những lần còn lại.
  • Giải thích sandbox là gì và cơ chế trên từng hệ điều hành: xem ghi chú ở Phụ lục.

3 · Secret: để agent không có gì đáng lấy

  • Không để secret plain text trong repo; dùng secret manager inject lúc chạy (op run, Doppler, Vault).
  • Token ngắn hạn, phạm vi hẹp. Publish npm, PyPI bằng trusted publishing qua OIDC, không còn token publish dài hạn trên máy dev.
  • Không đăng nhập sẵn tài khoản admin hay production trong shell của agent; production phải đăng nhập lại có MFA.

4 · MCP: đếm cạnh trước khi bật

  • Ghim phiên bản; chỉ dùng server chính chủ hoặc đã review; danh sách được phép ở cấp team.
  • Mỗi server một token riêng, quyền tối thiểu, chỉ đọc khi có thể. Không bao giờ dùng service_role hay token admin.
  • Không bật cùng lúc MCP đọc nội dung bên ngoài và MCP gửi được ra ngoài. Tắt tool không dùng.

5 · Chuỗi cung ứng của chính công cụ AI

  • Extension: biết editor lấy từ marketplace nào; cùng một ID trên mỗi marketplace là một chuỗi cung ứng riêng. Cập nhật trễ vài ngày thay vì tự cập nhật ngay.
  • File rule và skill: CODEOWNERS, review như code, cảnh báo ký tự ẩn trong diff, ghim phiên bản skill.
  • Package: lockfile, --ignore-scripts, kiểm tra tuổi và lượt tải package mới (pnpm minimumReleaseAge).

6 · Git và CI là chốt chặn cuối

  • Agent làm trên branch riêng, branch protection, không push main, không tự merge.
  • Review PR của agent như PR của đồng nghiệp mới; soi thay đổi ngoài phạm vi: workflow, cấu hình, test bị sửa. Secret scanning và SAST cho mọi PR.
  • Agent trong CI: chỉ người có quyền write kích hoạt, permissions: tối thiểu cho GITHUB_TOKEN, không có secret production trong job, cẩn thận pull_request_target, không nhúng thẳng nội dung issue/PR vào prompt, agent không sửa file workflow.

Demo: một file trong repo, rồi sandbox chặn lại

  • Comment ẩn trong một file; agent ở chế độ auto-approve đọc .env và gửi ra một server do mình dựng.
  • Sửa trên sân khấu: bật sandbox, deny .env, chặn mạng ra domain lạ. Chạy lại để thấy lệnh bị chặn.
  • Môi trường riêng, secret giả. Chuẩn bị video dự phòng. Xem thêm trang Demo.

Khi nghi đã dính

  • Ngắt mạng máy đó, báo team security.
  • Đổi mọi credential máy đó chạm được, làm từ một máy sạch. Gỡ extension hay package độc không xóa được backdoor; nên cài lại máy.
  • Tìm persistence và rà việc agent đã làm: transcript, shell history, package hay repo mình không tạo.

# Windows (PowerShell)

Checklist và hỏi đáp

Làm được ngay trong tuần này

  • Tắt auto-approve, deny đọc .env và thư mục credential, deny sửa cấu hình agent, allowlist lệnh
  • Bật sandbox của công cụ hoặc chạy agent trong devcontainer không mount credential
  • Dọn secret khỏi máy dev: secret manager, token ngắn hạn, trusted publishing
  • Rà MCP server đang bật: ghim phiên bản, token riêng quyền tối thiểu, tắt cái không dùng
  • Rà extension và skill; đưa CLAUDE.md, AGENTS.md, .cursorrules vào CODEOWNERS
  • Rà workflow có agent trong CI: ai kích hoạt được, GITHUB_TOKEN có quyền gì, job có secret nào

Câu hỏi khán giả hay hỏi

Gợi ý trả lời, chỉnh theo kinh nghiệm của bạn.

Dùng model mạnh hơn có chặn được prompt injection không?

Tỷ lệ bị lừa giảm nhưng không về 0, còn kẻ tấn công thì thử được vô hạn lần. Coi đó là một lớp lọc, không phải ranh giới.

Agent chậm đi vì phải hỏi nhiều quá thì làm sao?

Allowlist sẵn lệnh an toàn (test, lint, build) và bật sandbox, để chỉ phải hỏi ở lệnh có mạng hoặc ghi ra ngoài repo. Muốn chạy tự do thì chạy trong container không có credential và không có mạng ra ngoài.

Code dán vào công cụ AI có bị dùng để huấn luyện không?

Tùy gói: bản doanh nghiệp thường cam kết không huấn luyện và có chính sách lưu trữ riêng, bản cá nhân thì khác. Kiểm tra điều khoản của đúng gói công ty đang dùng.

Team nhỏ, không có security team thì bắt đầu từ đâu?

Ba dòng đầu của checklist: tắt auto-approve, bật sandbox, dọn secret khỏi máy dev. Ba việc này cắt được hai vòng của lethal trifecta.

Dùng khi khán giả hỏi "sandbox cụ thể là cái gì" ở phần Phòng thủ.

Sandbox là gì

  • Môi trường bị rào lại để chạy chương trình: bên trong muốn làm gì cũng được, ra ngoài rào thì không chạm tới được gì.
  • Với coding agent, sandbox quyết định agent đọc, ghi file nào, gọi mạng tới đâu, chạy được tiến trình gì.
  • Điểm mấu chốt: giới hạn do hệ thống áp đặt, không do AI tự giác tuân theo. Dặn trong prompt thì injection có thể lừa được; kernel từ chối thì không lừa được.

Hoạt động thế nào

  • File: chỉ thấy hoặc chỉ ghi được thư mục project; đọc ~/.ssh, ~/.aws thì kernel trả về "Permission denied".
  • Mạng: chặn hẳn, hoặc đi qua proxy chỉ cho phép vài domain như registry npm, PyPI.
  • Tiến trình con kế thừa giới hạn: agent chạy bash, curl, python thì các lệnh đó cũng bị rào y như agent.
  • Hai mức: sandbox tiến trình (OS rào một tiến trình trên máy thật) hoặc container, VM (agent có hẳn một "máy riêng", máy thật nằm bên ngoài).
