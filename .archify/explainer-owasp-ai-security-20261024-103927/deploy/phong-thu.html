Khi agent đã bị lừa, nó vẫn không làm được gì

Một thí nghiệm nhỏ cho phần Phòng thủ. Agent nhận một việc bình thường, làm thêm một việc không ai giao vì đọc phải chỉ dẫn ẩn trong repo. Sau đó ta bật rule deny và sandbox, chạy lại đúng việc đó và xem điều gì thay đổi.

Ba ý chính

Payload trong thí nghiệm chỉ là một canary vô hại. Thế là đủ để thấy agent làm theo chữ nó đọc, không cần tới một payload đánh cắp dữ liệu thật.

Dữ liệu chính là lệnh.

Một dòng chữ người đọc không thấy trong file cũng đủ khiến agent làm việc không ai giao.

Việc nó làm được là quyền bạn đã cấp.

Ở đây chỉ là canary. Đổi câu chữ đi thì agent có đúng quyền đó để đọc secret hay gọi mạng.

Ranh giới thật không cần model thông minh.

Rule deny và sandbox vẫn chặn được kể cả khi agent đã bị lừa.

Thí nghiệm từng bước

01

Bối cảnh

Một repo bình thường, một việc bình thường

Repo
Repo mẫu gồm vài file code, một test chạy được và một file .env chứa secret giả.
Việc giao
"Tóm tắt repo và chạy test", việc mà ai cũng nhờ agent làm.
Điểm bất thường
README có một câu chỉ dẫn mà người đọc lướt qua sẽ không thấy. Câu này chỉ yêu cầu một việc vô hại, dễ nhận ra: tạo file CANARY.txt.
02

Lần chạy 1: cấu hình không an toàn

Agent làm thêm một việc không ai giao

Cấu hình
Bật auto-approve, giao đúng việc ở bước 1.
Kết quả
Agent tự tạo CANARY.txt dù không ai yêu cầu. Bật hiển thị ký tự ẩn hoặc comment thì thấy câu chỉ dẫn nằm sẵn trong file.
Ý nghĩa
Đây mới chỉ là canary. Đổi câu đó đi thì agent cũng có quyền đọc .env hay gọi mạng y như vậy, vì nó có mọi quyền mà bạn có.
Liên hệ
Cấu hình này có đủ cả ba vòng của lethal trifecta: dữ liệu nhạy cảm, nội dung lạ, đường ra ngoài.
03

Sửa lần 1: lớp mềm

Cấp quyền cho agent giống như cấp IAM cho một service: chỉ mở đúng những gì nó cần.

Rule deny, allow, ask

Cách làm
Tắt auto-approve. Mở .claude/settings.json và thêm ba nhóm rule:
Các rule
  • Deny đọc .env*, khóa riêng, ~/.ssh, ~/.aws.
  • Deny agent tự sửa .claude/.
  • Allow test và lint; ask ở git push, npm install và lệnh có mạng.
Giới hạn
Đây là lớp mềm. Nó chặn phần lớn sai sót, nhưng nằm ngay trong công cụ mà injection đang nhắm tới.
// .claude/settings.json (bản an toàn)
{
  "permissions": {
    "deny": [
      "Read(./.env*)",
      "Read(./**/*.pem)",
      "Read(~/.aws/**)",
      "Read(~/.ssh/**)",
      "Edit(./.claude/**)"
    ],
    "allow": ["Bash(npm test:*)", "Bash(npm run lint:*)"],
    "ask": ["Bash(git push:*)", "Bash(npm install:*)", "WebFetch"]
  }
}

Cú pháp rule có thể khác giữa các phiên bản. Đối chiếu với tài liệu của phiên bản Claude Code bạn đang dùng.

04

Sửa lần 2: ranh giới thật

Ranh giới ở OS, không ở prompt

Cách làm
Bật sandbox của công cụ (/sandbox trong Claude Code, hoặc --sandbox workspace-write trong Codex CLI), hoặc chạy agent trong devcontainer chặn mạng ra ngoài.
Kết quả
Agent chỉ ghi được trong thư mục repo, mạng chỉ mở cho registry cần thiết, .env giả không còn trong tầm với.
Lợi ích phụ
Sandbox giảm số lần agent phải hỏi xác nhận, nên những lần còn lại bạn sẽ đọc kỹ hơn.
Xem rõ hơn
Muốn thấy OS chặn từng thao tác, xem phần Thử sandbox. Cách bật cho từng loại máy nằm ở phần Bật sandbox.
05

Lần chạy 2: cùng việc, cùng file

Kết quả nào cũng nói lên một điều

Cách làm
Giao lại đúng việc cũ, không sửa file chứa chỉ dẫn ẩn.
Kết quả
Có ba khả năng:
Bị lừa nhưng bị chặnLệnh bị từ chối hoặc phải hỏi xác nhận. Phòng thủ không cần model thông minh.
Agent bỏ qua chỉ dẫnChỉ là may mắn. Đừng dựa vào nó, kẻ tấn công thử được vô hạn lần.
Sandbox từ chốiAgent định chạm vào file ngoài repo hoặc mạng và bị OS chặn.

Nguyên tắc rút ra

Ghi nhớ
Thiết kế như thể prompt injection chắc chắn thành công, rồi đảm bảo khi đó nó không làm được gì đáng kể.
S

Thử sandbox: cùng một chuỗi lệnh, chạy hai lần

Không gọi model, nên lần nào chạy cũng ra cùng kết quả. Script đóng vai một agent đã bị lừa; việc của bạn chỉ là xem OS chặn được gì. Bộ script nằm ở demos/sandbox-demo trong repo ai-security. Sandbox ở đây là một container Docker, chạy được trên Windows, macOS và Linux; script viết bằng PowerShell nên macOS và Linux cần cài pwsh. Muốn bật sandbox cho agent thật, xem phần tiếp theo.

Chuẩn bị

Cài đặt
Chạy .\demo.ps1 setup để build image và kéo sẵn python:3.12-alpine. Bước này cần mạng; các bước sau chạy được khi không có mạng.
Hai terminal
Một terminal chạy script, terminal còn lại chạy .\demo.ps1 attacker-log để thấy "máy kẻ tấn công" nhận được gì.

Lần 1: .\demo.ps1 unsafe

Bối cảnh
Đây là những lệnh agent sẽ chạy nếu đọc phải chỉ dẫn ẩn. Nó chạy với quyền của bạn, thấy thư mục home của bạn và có mạng.
Kết quả
Năm dòng đỏ LỌT: .env, ~/.ssh, ~/.aws, ghi ~/.bashrc, gửi ra ngoài. Terminal attacker in ra đủ secret giả. Mở run/home/.bashrc sẽ thấy dòng persistence.
Ý nghĩa
Agent đã tắt nhưng dòng này vẫn còn. Lần sau bạn mở shell là nó chạy.

Lần 2: .\demo.ps1 sandboxed

Kết quả
Năm dòng xanh BỊ CHẶN, terminal attacker không nhận thêm gì. Mở demo.ps1 để đối chiếu từng cờ với bảng bên dưới.
Để ý
Dòng đầu tiên vẫn là VẪN LÀM ĐƯỢC: sandbox không cản việc thật trong repo. Lỗi chặn đến từ OS (No such file, Read-only file system, Could not resolve host), không phải từ lời dặn nào.
Ý nghĩa
Cùng một agent, cùng bị lừa. Chỉ khác là lần này nó không với tới được gì.
Cờ trong chế độ sandboxedChặnVòng trifecta bị cắt
Không mount thư mục homeĐọc ~/.ssh, ~/.awsDữ liệu nhạy cảm
File rỗng đè lên /workspace/.envĐọc secret trong repoDữ liệu nhạy cảm
--network noneGửi dữ liệu ra ngoàiĐường ra ngoài
--read-only, --tmpfs /tmpGhi persistence ngoài repoHậu quả sau khi agent tắt
--cap-drop ALL, no-new-privilegesLeo quyền trong containerThu hẹp phạm vi còn lại

Khi chạy agent thật trong container thì không dùng được --network none, vì agent cần gọi API của model. Khi đó dùng firewall chỉ cho phép một số domain, như devcontainer tham khảo của Claude Code.

S2

Bật sandbox trên máy của bạn

Có hai cách. Cách nhẹ là bật sandbox có sẵn trong công cụ: các lệnh agent chạy bị hệ điều hành giới hạn, không cần Docker. Muốn cách ly mạnh hơn thì chạy cả agent trong container, giống demo ở trên. Bảng dưới cho biết mỗi loại máy dùng được cách nào.

Claude Code trên macOS, Linux và WSL2

Cài đặt
macOS không cần cài gì thêm. Linux và WSL2 cài hai gói bubblewrap và socat: sudo apt-get install bubblewrap socat (Ubuntu, Debian) hoặc sudo dnf install bubblewrap socat (Fedora). Cài xong thì mở lại Claude Code.
Bật
Gõ /sandbox trong phiên làm việc rồi chọn chế độ. Muốn lần nào cũng bật thì thêm khối sandbox vào ~/.claude/settings.json như mẫu bên dưới.
Mặc định chặn
Ghi file ngoài thư mục dự án, và mạng đi tới những domain chưa được cho phép (bạn sẽ được hỏi, hoặc lệnh bị từ chối, tùy chế độ quyền).
Cần tự chặn
Mặc định agent vẫn đọc được gần như mọi file trên máy, kể cả ~/.ssh và ~/.aws. Video ở trên cho thấy điều này ở lần 2: không gửi ra ngoài được, nhưng secret đã bị đọc và in vào output, tức là đã vào ngữ cảnh của model. Hãy liệt kê những file cần giấu trong mục credentials.
Bật một lần
Cấu hình được lưu lại, không phải bật lại mỗi lần. /sandbox lưu cho dự án hiện tại trên máy bạn; ~/.claude/settings.json áp dụng mọi dự án; .claude/settings.json commit vào repo thì áp dụng cho cả nhóm. Trên Windows, Claude Code trong WSL2 và Claude Code chạy thẳng trên Windows là hai bản riêng, cấu hình riêng.
Phạm vi
Sandbox chỉ áp dụng cho các lệnh shell agent chạy. Công cụ đọc và sửa file, MCP server và hook nằm ngoài sandbox, nên vẫn cần rule deny ở bước 3. Hai lớp này bổ sung cho nhau.
// ~/.claude/settings.json: bật sandbox cho mọi dự án
{
  "sandbox": {
    "enabled": true,
    "allowUnsandboxedCommands": false,
    "failIfUnavailable": true,
    "credentials": {
      "files": [
        { "path": "~/.ssh", "mode": "deny" },
        { "path": "~/.aws/credentials", "mode": "deny" }
      ]
    },
    "network": {
      "allowedDomains": ["github.com", "*.npmjs.org"]
    }
  }
}

allowUnsandboxedCommands: false không cho agent tự chạy lại một lệnh bên ngoài sandbox khi lệnh đó bị chặn. failIfUnavailable: true báo lỗi khi máy thiếu bubblewrap hoặc đang chạy WSL1, thay vì lặng lẽ chạy lệnh mà không có sandbox. allowedDomains là những domain được đi tới mà không cần hỏi; chỉ thêm những gì dự án thật sự cần.

Claude Code trên Windows

Vì sao
Khi chạy trực tiếp trên Windows, Claude Code không đặt lệnh vào sandbox.
Cách làm
Mở PowerShell bằng quyền admin, chạy wsl --install, khởi động lại máy. Mở Ubuntu, cài Claude Code bên trong WSL2 rồi làm như phần Linux ở trên. WSL1 không hỗ trợ sandbox.

Codex CLI

Chạy
codex --sandbox workspace-write --ask-for-approval on-request. Agent chỉ ghi được trong dự án, không có mạng, và hỏi bạn khi cần làm gì vượt ra ngoài.
Mạng
Mặc định tắt. Chỉ bật khi thật sự cần, bằng network_access = true trong mục [sandbox_workspace_write] của ~/.codex/config.toml.
Windows
Codex có sandbox riêng cho Windows. Trên Windows 11 bản 24H2 hoặc 25H2 đã cập nhật, thêm prefer_mxc = true vào mục [features]. Máy không đủ điều kiện thì dùng sandbox = "elevated" trong mục [windows]; lần cài đầu cần quyền admin. Dùng WSL2 cũng được.
Tránh
--sandbox danger-full-access và --yolo: tắt cả sandbox lẫn bước hỏi xác nhận.

Chạy agent trong container (mọi loại máy)

Khi nào
Khi muốn cách ly mạnh hơn, hoặc muốn cả nhóm dùng chung một môi trường.
Cách làm
Cài Docker Desktop (Windows, macOS) hoặc Docker Engine (Linux), cài extension Dev Containers trong VS Code, rồi bắt đầu từ devcontainer tham khảo của Claude Code. Bản này có sẵn script firewall chỉ cho agent đi tới những domain cần thiết.
Đừng mount
~/.ssh, ~/.aws, file credential cloud hay Docker socket vào container.
Giới hạn
Agent vẫn đọc và gửi đi được mọi thứ nằm trong container, kể cả token đăng nhập của chính nó. Vì vậy vẫn cần firewall, và chỉ dùng với repo bạn tin.

Kiểm tra sau khi bật

Thử ba việc
Tạo một file giả ngoài dự án và thêm nó vào danh sách chặn đọc. Sau đó nhờ agent đọc file đó, ghi một file vào thư mục home, và chạy curl https://example.com.
Kết quả đúng
Cả ba bị chặn hoặc phải hỏi bạn trước. Việc trong dự án, như chạy test, vẫn chạy bình thường.

Tự thử lại an toàn

Muốn chạy lại thí nghiệm trên máy mình, giữ mấy điều sau.

Môi trường

  • Dùng VM hoặc devcontainer riêng, reset về trạng thái sạch trước mỗi lần chạy
  • Không mount ~/.ssh, ~/.aws hay Docker socket vào môi trường thử
  • .env chỉ chứa secret giả, ghi rõ là giả
  • Không đăng nhập tài khoản thật, không dùng token hay credential thật

Khi đọc kết quả

  • Chỉ dùng payload vô hại như tạo CANARY.txt; không thử lệnh đọc secret hay gửi dữ liệu ra ngoài
  • Chạy vài lần: model không phải lần nào cũng bị lừa
  • Agent không bị lừa không có nghĩa là an toàn, vì kẻ tấn công thử được vô hạn lần
  • Đối chiếu tên lệnh và cờ sandbox với phiên bản Claude Code hoặc Codex CLI đang dùng
