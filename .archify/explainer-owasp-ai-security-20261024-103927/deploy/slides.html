04 · Phòng thủ

Đừng hỏi chặn thế nào. Hãy hỏi bị lừa thì nó làm được gì.

Lớp mềm

  • Dặn trong CLAUDE.md
  • Rule deny trong file cấu hình
  • Hỏi xác nhận từng lệnh

Ranh giới thật

  • Sandbox ở mức OS hoặc container
  • Không có secret đáng lấy trong tầm với
  • Token ngắn hạn, phạm vi hẹp
Không thể chặn prompt injection 100%. Câu hỏi đúng: nếu agent bị lừa thì nó làm được gì, và làm sao giảm phạm vi đó. Lớp mềm vẫn nên có, vì nó chặn phần lớn sai sót vô tình. Nhưng không được là lớp duy nhất.
04 · Phòng thủ · Quyền

Cấu hình quyền cho agent như IAM cho một service

1 · Deny đọc .env, ~/.ssh, ~/.aws
2 · Deny sửa cấu hình của agent
3 · Allowlist test, lint, build
4 · Hỏi ở mạng, push, install
5 · Hook chặn lệnh nguy hiểm
// .claude/settings.json
{ "permissions": {
  "deny": ["Read(./.env*)",
           "Read(~/.aws/**)",
           "Read(~/.ssh/**)",
           "Edit(./.claude/**)"],
  "allow": ["Bash(npm test:*)"],
  "ask": ["Bash(git push:*)",
          "Bash(npm install:*)",
          "WebFetch"]
}}

Rule deny chỉ là lớp mềm. Ranh giới thật nằm ở OS hoặc container.

[DEMO CẤU HÌNH] Chuyển sang editor, mở file thật, sửa trước mặt người nghe. Dòng 2 trả lời trực tiếp CVE ở cửa 1: agent không được tự ghi .claude/, .vscode/settings.json, .cursor/mcp.json. Hook: PreToolUse trong Claude Code chạy script của bạn trước mỗi lệnh, chặn được curl ra domain lạ hay rm -rf. Cursor và Copilot có cơ chế tương đương. Commit file cấu hình này vào repo để cả team dùng chung.

04 · Phòng thủ · Secret

Để agent không có gì đáng lấy

  • Không để secret plain text trong repo
  • Secret manager inject lúc chạy: op run, Doppler, Vault
  • Token ngắn hạn, phạm vi hẹp; publish npm bằng trusted publishing
  • Không đăng nhập sẵn tài khoản admin hay production trong shell của agent
Đây là cắt vòng "dữ liệu nhạy cảm". Rule deny .env vẫn bị vượt qua được (agent chạy cat qua một script khác); không có file thì không có gì để lộ. Trusted publishing (npm, PyPI): CI publish qua OIDC, không còn token publish dài hạn nằm trên máy dev, nên bước "token npm" trong chuỗi ở slide 20 biến mất. Tách profile cloud: dev mặc định, production phải đăng nhập lại có MFA.

Rà chuỗi cung ứng của chính công cụ AI

grep svc-telemetry ~/.ssh/authorized_keys

Cùng một ID extension trên mỗi marketplace là một chuỗi cung ứng riêng. Mã độc chạy lúc nạp, nên công cụ chỉ quét lúc cài sẽ không thấy. Tunnel là kết nối đi ra, firewall chiều vào không cứu được. Package mới: tuổi, lượt tải, repo nguồn. pnpm có minimumReleaseAge để chỉ cài bản đã ra đủ lâu. Đã cài extension 2.1.313: coi máy là đã bị chiếm (slide 32).

04 · Phòng thủ · Khi đã dính

Nghi máy đã bị chiếm thì làm gì?

  • Ngắt mạng máy đó, báo team security
  • Đổi mọi credential máy đó chạm được, từ một máy sạch
  • Tìm persistence: authorized_keys, LaunchAgents, cron, scheduled task
  • Rà việc agent đã làm: transcript, shell history, package đã publish
Gỡ extension hay package độc không xóa được backdoor đã cài. Nên cài lại máy. Đổi credential từ máy sạch: làm trên máy bị chiếm thì token mới lộ tiếp. Rà npm, PyPI, GitHub: có phiên bản hay repo nào mình không tạo không.

Thiết kế như thể injection chắc chắn thành công

Rồi đảm bảo khi đó nó không làm được gì đáng kể.

Thông điệp chốt. Bước ra giữa sân khấu, nói CHẬM, dừng sau mỗi vế. Nhắc lại bốn câu hỏi: agent có quyền của bạn · sáu cửa vào · hậu quả lan ra ngoài máy bạn · cắt bớt vòng trifecta bằng sandbox và secret.

Làm ngay trong tuần này

  • Tắt auto-approve, deny .env và cấu hình agent, allowlist lệnh
  • Bật sandbox của công cụ hoặc chạy trong devcontainer
  • Dọn secret khỏi máy dev: secret manager, token ngắn hạn
  • Rà MCP: ghim phiên bản, token riêng, tắt cái không dùng
  • Rà extension, skill; đưa CLAUDE.md, AGENTS.md vào CODEOWNERS
  • Rà workflow có agent: ai kích hoạt, GITHUB_TOKEN có quyền gì
Mời khán giả chụp ảnh slide này. Bấm từng dòng, mỗi dòng gắn với một slide phòng thủ đã nói.
